# TESTING.md — dsh-shell-host 验证分层与证据纪律

> 与相邻工作区（matt 工作流，`<sibling-repo>/tests/`）**同步对齐**的口径
> （2026-10-16）。两边规则同构，便于跨工作区互读证据。

## TEST SCOPE TIERING（选最小能证明当前改动的档，并在票的 evidence 行点名）

| 档 | 范围 | 何时用 |
|---|---|---|
| **① minimal relevant** | 触及改动的单个测试文件 / target | 迭代时 |
| **② single-module** | 该模块/包自己的套件 | 改动局限在单模块内 |
| **③ full high-risk suite** | 完整 verify 集（+ e2e） | 票关闭时；以及改动触及**高危面** |

对应命令（Windows 权威树；迭代别拿 `node --run test` 当单档用）：

- **单档**：`node node_modules/vitest/vitest.mjs run --project unit tests/<file>.spec.ts`（machine 档换 `--project machine`）
- **单车道**：`node scripts/verify-all.mjs --lane unit`（msys 侧是 `bash scripts/msys-lane.sh --lane machine`）
- **收集口径**：unit 车道按**位置**收集（`#44`）—— 新增 `tests/**/*.spec.ts` 无需登记；machine 车道是
  `vitest.config.ts` 的显式清单（只放串行、碰真实环境的档）。所以新增/改动 spec 时不必再去读元守卫档
  确认"要不要登记"。
- **计费档（真实端点）别用单档出绿**：`tests/e2e-real-llm-machine.spec.ts` 的绿路径必然跑到环 6
  （真实端点，一次 ≈22k token）。迭代只跑**红路径 / 变异单档**（环 3 一红就按名阻断环 4–6，零 token），
  绿路径读数交给 `node --run test` —— AC 要的本来就是它。#101 会话实测：4 次变异单档共 ~36s、0 token。
- **验收口径**仍只有 `node --run test`：`--lane` 的输出自带「非验收口径」提示，别把单车道读数当验收。

本仓高危面：**loader 行 / 组合树 / 入口导出（pty·terminal·wsl）/ 原生件路径 /
依赖锚（peer、RC 锚）**。

## 证据纪律（硬规则）

- **声明你未跑的，是证据的一部分，绝不是证据的替代。**
  跳过必须显式写成 `not run locally: X`。
- **响亮跳过（loud skip）**：门禁未满足时**必须打印 `!! SKIP (loud)` 并说明缺什么**，
  绝不静默当 pass。
- **证据日志落地固定 `NO_COLOR=1`**：跨会话比对证据行格式会失配，固定 `NO_COLOR=1` 才有可比性。
  **注意这已不是 `verify-all` 能否解析的前提**（#122 已把读数与颜色解耦）：`verify-all` 自己
  spawn 测试运行器时把形态钉成 `NO_COLOR=1`，且解析层两种形态都认（裸 `|lane|` 与带色的
  色块徽标），故调用者会话带不带色，逐文件表都完整。**你在 `verify-all` 之外**（例如直接跑
  vitest 抓日志）落地证据时，仍请显式 `NO_COLOR=1`。
  历史根因与修法见 #122；`verify-all` 侧另有响亮失败兜底（解析不到行但 vitest 报过用例数 ⇒ FAIL）。
- **证据必须点名层级**（mock 层 / 真实层），因为两层能证明的东西**不同**。
- **票面的"根因 / Current behavior"是待验假设，不是事实**（#123 retro C1，
  同一形态已计次 3：`#91` → `#122` → `#123`）。实现前**必须**有一条自己造的读数，
  能把"**现象**"与"**机理**"分开 —— 否则会照着现象修出**修不掉那个洞**的东西。
  - **正例（#123）**：票面写"两处前置门槛都是等一次出现式：窗口重新打开时无处躲"，
    按字面读修法就是"等更久"。**实测推翻**：那次红的时候门禁**自己一个字都没报**
    （`.scratch/t123-repro-3.log` 里没有"未就位"）⇒ 它**探到过齐** ⇒ 真机理是
    **check-then-use**（探到齐 → 写者删了 → 下游早退）。差别是实质的：等更久**永远**
    会在等待结束后重开窗口，而 check-then-use 的洞在"探"与"用"之间。
  - **正例（#122）**：票面写"解析对颜色敏感"，真相是"色块形态按**空格数**判别"——
    按现象修（容忍颜色）会漏掉对齐填充那条路。
  - **反例形状**：一条"能复现现象"的命令**不足以**当机理证据 —— 它只说明现象在。
    要的是**能把两种解释分开**的读数（上面那条"门禁自己报没报"就是：报了 = 等不到；
    没报 = 探到过又被删，一句话就能分开）。
  - 本仓的 `diagnosing-bugs` skill 的 Phase 1（tight feedback loop）要求"一条命令在这
    **bug** 上变红"，本条是它的**姊妹**：那条要求"能复现"，本条要求"能**区分解释**"。
  - **"风险量级 / 余量 / 扫描面"同样是待验假设**（批 D 聚合 A4；`#129` C3 + `#126` D5，上条的推广）：
    票面给的**余量推算可能偏松** —— `#129` 票面称 REG 档"约 1.5×"，实测（真 core、1ms 探针、n=20）
    **最坏只剩 3ms**（1.03×）；实测**更紧**时按实报，别让票面的乐观数字进证据。
    票面的**扫描面**也可能与同文件既有判据**取向相反**（`#126` 票面写 `docs/**` 字面含 `adr/`，
    而该文件既有第 4/5/6 条断言**排除** `adr/`）⇒ **立票阶段**就应自查并写明取哪个，
    否则实现者只能二选一：静默从惯例（等于改票面）或停下来问（浪费一次往返）。
- **"造不出红"本身就是机理信息**（批 D 聚合 A9，`#129` C4）。tight loop 要"一条命令在这个 bug 上变红"；
  但**当这个构造反复失败时，失败常常在告诉你"假设的失败路径不是真的那条"**。
  - **实测（`#129`）**：三个版本全部失败 —— v1 先阻塞则预算在阻塞**之后**才计时（阻塞被吸收）、
    v2 `await sleep(budget)` **本身让出事件循环**（被饿住的回调总能拿到那一轮）、
    v3 争用不足以翻转。由此得到的机理是"**固定 sleep 的代价不是回调被饿死，
    而是预算是对真实耗时的墙钟猜测**"—— 这个结论比任何一次"构造成功"都值钱。
  - ⇒ 此时应留档**失败构造** + 另找**有判别力**的读数（实测余量 / 重负载 A/B / 故障注入），
    **不要**把探针调到"能红"为止 —— 那是**为了结论调探针**。
  - **探针迭代不要复用同一份日志名**：`#129` 的 v1/v2 日志被 v3 **同名覆盖**
    ⇒ "三次失败"只剩文档里的**声称**，不是可复跑的一手证据。每轮用**不同**文件名。
- **判别力 / 顺序 / 优先级类 AC 的变异取证 = 同一个失败注入 + 两个顺序各跑一次**
  （批 E 聚合 E4，计次 ×2：`#103` 票面给的"改坏形态"样本**跑不红**；`#100` 的 AC③ 是
  "归因断言先于 `stderr 空`"）。只跑"新形态绿"证明不了**顺序有意义**，那只说明它没红。
  - **正例（`#100`）**：注入一段会被归因的 stderr，① 新序 → 第一条红**正是归因**
    （`stderr never blames this bundle's loader rows`）；② 把空断言挪回最前 → 第一条红是
    「instance stderr is clean」、归因**永远走不到** —— **② 是反证样本**，它把票面点名的
    缺陷形状直接演示成一次红。两轮读数都留档，才算"判别力"而不是"改完了没报错"。
  - 同理，"**改坏样本**"（票面给的变异例子）要先跑一次确认**它真能变红**；
    造不出红本身是机理信息（见上文"造不出红本身就是机理信息"），不是"可以跳过"。`
- **验收口径的套件必须在最后一次写入之后起跑**（`node --run test` / `test:release`）：
  跑完 `git diff` 为空（或起跑前后文件 hash 一致）才采信输出。跑着的时候改文件 =
  跑的那份不是要交付的那份，只能重跑 —— 2026-10-16 实测踩过一次（多烧一轮全量套件）。
  **review 阶段的修改同样算写入**：`implement` 流程里 review 排在最终全量**之前**（review 读
  staged diff 即可，不必先提交），否则 review 一改就作废前一次全量 —— 2026-10-17 实测：一次
  三文件的测试面改动起跑了 3 次全量，其中一次完整跑的存在只因为 review 落在它之后。
  **且等其它 agent / 子代理静默之后再跑**：并发负载会扰动真实层（#97 会话唯一一次真实
  端点 `TRANSPORT` 恰好落在两个复核 subagent 与全量套件并跑的窗口里，此后未并跑的四次
  真实回合全绿 —— n=1 的观察，当**顺序纪律**用，别当因果结论）。
  - **排程纪律：先审读 + 定稿，再起跑全量**（批 D 聚合 A7，`#126` D4 实测）。
    **审读自己的新代码**是起草阶段的常规动作，而它**必然**发生在"起跑全量"之后（因为全量要等）
    ⇒ 二者**结构性冲突**。`#126` 就是在这个等待窗口里改了 5 处过时函数名
    ⇒ 那一轮全量**被测的不是要交付的那份** ⇒ 作废、白烧一轮（含真实层计费环 ~22k token）。
    ⇒ 等待期间**只读**；要改就等它跑完再改、然后**重跑**。
  - **任何写盘之后都要在最终树上重跑交付读数**（批 E 聚合 E1，`#100` 实测）：
    **变异复原也算写盘** —— 复原后只复跑被变异的那一档，另两档的绿就**早于**最终树
    （`#100` 实测：挂具 12:13 复原，tarball 12:08 / 真实层 12:09 的绿都已过期，两轴各报一次
    「交付态缺读数」）。顺序固定为 `改 → 单档 → 两轴 → 按发现改 → 全量 → 提交 → 车道`
    （同一条写在 [code-review-brief.md](../code-review-brief.md) §1）。
- **修复改变了"被测面"时，AC 证据必须给同面 A/B**（#123 retro C2）。
  凡修复动的是**面本身**（车道划分、门禁条件、环境变量、开关、并行度），在**改变后的面**上
  重复跑 N 次**结构上不可能复现**原现象 —— 于是"N 次全绿"证明的是"改动被应用了"，
  **不是**"那个洞没了"。
  - **正例（#123）**：#123 的修复就是"把写者 `clean-lib.spec.ts` 移出 unit 车道"。
    初版 AC 证据跑 `verify-all.mjs --lane unit` —— 那个面**不含 writers**，写者根本不在池里，
    全绿是必然的。**Spec 轴复核独立抓到**这一点。补**同面 A/B** 后才有判别力：
    A 形态（writers **并回** unit = 修复前划分）**0 绿 / 6 红**、B 形态（本票划分）
    **6 绿 / 0 红** —— 同一 driver、同一机器、**同一份测试代码**，唯一变量 = 车道划分。
    （证据：`.scratch/t123-ab2-{A,B}-{1..6}.log`。）
  - **落法**：把"修复前形态"用**临时 config / 环境变量 / 开关**表达出来（**不写产品文件**，
    跑完即删），与"修复后形态"跑同样的 N 次，并在证据行里**声明唯一变量**。
  - **为什么容易漏**：修复与被测面同源时，"在哪个面上重复"看起来是个无关紧要的选择题。
  - **要报"判别力出现在哪个条件下"，且不判别的那一轮也要在证据里**（批 D 聚合 A10；`#129` C5）：
    该票轻负载下 **A 6/6 = B 6/6（NOT DISCRIMINATING）**，加重负载后才是
    A **FAST 3/6、REG 2/6** vs B **6/6**。**只报后者等于选择性举证** ——
    读者会以为"旧形态本来就常红"。声明判别力的**出现条件**是证据的一部分。
- **"空日志"与"没跑"不可区分 —— 空输出不能单独当证据**（#123 retro C3）。
  验收类命令一律**经 driver 落一行 `exit=<code>`**（形状见 `.scratch/t123-ac.mjs` /
  `t123-ac2.mjs`），或至少让读数**自带**那个数字。
  - **为什么本仓特别容易踩**：`typecheck` 是**成功即无输出**，于是"0 字节日志"成了
    最像证据的形状 —— #123 会话真的在 landing 里写过"空输出 = 干净"，
    而两轴复核**都**抓到那次 AC4 的日志是 0 字节（那一次其实在跑、最终绿，但**当时**不可证）。
  - **反方向同样会踩：读到空，可能只是"读早了"**（批 D 聚合 A6，`#126` 实测）。
    用 `(Get-Item $log).Length` 在命令**还在跑**时读文件，会稳定读到 **0** ——
    `#126` 据此一度写下"日志 0 字节"，事后复核是 **3769 字符**。
    ⇒ **判据是 `.exit` 文件存在**（它证明命令已结束），而不是在跑的过程中测日志长度。
- **引用一条读数时，那条证据此刻必须能打开**（批 E 聚合 E3，`#100` 实测：
  一条排程失误被两轴各判一次硬违规）。落地文档 / 提交信息 / 汇报里的每条读数，
  写之前先确认对应的一手输出**已经存在**（`.exit` 或等价物）；尚未产生的只能写成
  `not run — 计划于 <哪一步> 之后`，**不得**先写路径再补读数。
  - **派发两轴时同样适用**：brief 里要写明**证据面的当前状态**（哪些读数已产生、
    哪些还要跑），否则审阅者只能把"路径指向不存在的文件"判成**假事实**。
  - 推论：**"见下"这类前向引用**要么指向已经存在的段落，要么就别写 —— `#100` 落地文档
    §四 当时还是"（待填）"占位，指向它的那句被 Standards 轴按悬空引用报出。
- **「已推送 / 已关闭 / 已在 list 里 / 已同步」这类**当刻状态**声称，写之前先跑那条能证伪它的
  命令，把读数写进证据行**（`#132` 次-2；形态来自 `#130` 表第 4 次：汇报写了"批次外即时改动
  随批次末一并推送"，实测**没被推** —— 推送时被 `stash` 走了，推的是已提交的 commit）。
  **它与上一条是两条**：上一条管"被引的**文件**支不支持这个声称"，这一条管"**没有**被引文件、
  只有一个当刻状态"。
  - 落法：`git log origin/main..HEAD`（已推送 ⇒ 输出为空）/ `git status -sb` /
    `gh issue view <n> --json state`；跑不了（例如本机没有 `gh`）就写 `not run — <理由>`。
  - 为什么必须实测：状态声称**没有载体可核对**，"看着对"与"确实对"在文本上不可区分 ——
    这正是机械守卫（`tests/evidence-citations.spec.ts`）结构上覆盖不到的那一半。
- **判据本身会被行尾形态静默翻转 —— 锚行尾的正则必须考虑 CRLF**（批 D 聚合 A1，`#126`）。
  本仓**结构性存在两个行尾不同的树**：权威树是 **LF**，msys 部署副本被 `core.autocrlf`
  转成 **CRLF**（见 `docs/dev-environment.md` §0.1 第 1 条）。`text.split("\n")` 之后每行带尾随
  `\r`，而 JS 的 `$`（无 `m` 标志）匹配**串尾**、`[ \t]*$` 也收不下 `\r`
  ⇒ **以 `$` 收尾的判据在 CRLF 树里可能整体失效**。
  - **实测（`#126`）**：围栏守卫的两个正则都以 `$` 收尾 ⇒ 权威树（LF）**全绿**、
    两轴复核**全绿**、`node --run test` **全绿**，而 pre-push 车道在 msys 副本（CRLF）里**红**：
    `docs/research/research-official-terminal-ralph-bundles.md:395（该开栏没有闭栏）`
    （该行实为文档末尾的合法闭栏 —— 报错本身就是假的）。
    机理：第 1 行的开栏匹配不上（`$` 收不下 `\r`），而 `split("\n")` 使**末行不带 `\r`**
    ⇒ 末行反被认成开栏 ⇒ **完全虚假的红**（同一份文档、同一份内容，只是行尾不同）。
  - **为什么既有判据没暴露它**：第 4/5/6 条（路径 / 链接 / 哈希）**不要求匹配到行尾**，
    `\r` 对它们无害 ⇒ **只有新写的、锚行尾的判据会踩**。
  - **落法**：判据的对象是**内容语义**，行尾是**检出配置**的产物 ⇒ 判前先归一化
    （逐行 `replace(/\r$/u, "")` 或整体 `replaceAll("\r\n", "\n")`），
    并**补一条 CRLF 回归用例**；该用例要**同时锁住"未归一化时真会假报"**，
    否则正向那条断言就是**同义反复**（不能证明它守住了什么）。
   - **"补 CRLF 回归用例"按判据分两类**（批 E 聚合 E11，`#103` 实测：照字面写出的正向
     invariance 用例被 Standards 轴判成同义反复**硬违规**）：
     **(a) 判据要归一化** → 必须有"未归一化会假报"的**否定用例**（拿掉归一化就红）；
     **(b) 判据不锚行尾**（本仓四条展开值探针都不锚 `$`）→ 只需一条 LF/CRLF 都命中的
     invariance + 一条**锚行尾对照**（展示 A1 的翻车形态）即可，**不要求**从被证判据里
     硬造一个假报 —— 硬造出来的那条守住的只是它自己。
  - **自验口径**：判据类改动至少在**一种非 LF 行尾**下跑一遍。本仓最省力的做法其实是
    **看 pre-push 车道**（它天然在 CRLF 副本里跑）—— 但那意味着**推送时才知道**；
    更早的做法是自己临时造一份 CRLF 副本先跑一次。
- **读数里的"等待 / 超时 / 重试 / 预算"数字必须报**实测值**，不是配置上界**（#123 retro C4）。
  两者若都写，必须**可区分**且**实测值在前**。
  - **反面现场（#123 自查）**：loud skip 文案打印「等构件 **60000 ms** 仍未就位」，
    而它实际只等了 **2073 ms**（`absentRounds` 提前收手）—— 差一个数量级。
    在一个**专治"读数与事实不符"**的票里出现读数失真，是本条存在的最好理由。
    改后形态：`在 2073 ms（实际等待；配置上界 60000 ms）后仍未就位`。
  - 推论：任何"提前收手"的等待都**必须**把"为什么提前"与"实际等了多久"一起报出来，
    否则读者会把"早退"读成"等满"。
  - **推论二：「文件级通过数不变」与「用例级通过数增加」要同时报**（批 D 聚合 A12，`#126` D6）：
    `node --run test` 的汇总数的是**文件级**通过数（如 `OK — 28/29 通过`），
    而单档 / 全量 unit 报的是**用例级**（`#126` 是 45 / 443，基线 435）。
    只加用例、不加 spec 文件时，汇总数字**逐字不变是预期** —— 但读者会合理地怀疑
    "新增的判据没被跑" ⇒ **两处计数互相印证着报**（本仓 `#126` 的落地文档就是这么写的）。
  - **推论三：跨会话比车道读数时，先对齐 loud skip 的构成**（批 E 聚合 E8，`#100` 实测）：
    同一提交 `0cca8ae` 上两次 `--no-live` 车道给出 **479 passed / 7 skipped** 与
    **481 passed / 5 skipped** —— 差异全在 `tests/terminal-machine.spec.ts` 的 loud skip
    （**1↔3** 个环境门禁用例），两次都 `failed=0`、`exit=0`、文件数相同。
    ⇒ 判据以 **exit + failed 数** 为准；报"skip 数变了 / 回归了"之前，先看 per-file 的
    `(N tests | M skipped)` 行确认构成是否变了。
- **实验标记要死掉再提交**：变异 / 调试探针一律带唯一前缀（`[DEBUG-…]`；变异用
  `[MUTATION-…]`），口径见 `.claude/skills/diagnosing-bugs/SKILL.md` 的 Phase 4「Tag every
  debug log」与 Phase 6 清单 —— 提交前 grep 前缀应为 **0 命中**。`.githooks/pre-commit`
  已在 `tests/**`、`src/**` 的新增行上机械拦这一条（本仓修复类票的常规取证手段就是变异，
  漏回滚 = 提交物与被跑过的树不是同一份）。
  - **清理用的 grep 必须限定面**（批 E 聚合 E7，`#100` 实测）：
    `git grep -nE '\[(DEBUG|MUTATION)-' -- tests/ src/`。不限定面时**规则文本自身**就会命中
    （本文件、`.githooks/pre-commit`、诊断技能的 SKILL 都写着那两个前缀）——
    `#100` 实测 6 处命中**全是规则叙述**，按"0 命中"的字面读会得到假红，或逼人删文档。
    `.githooks/pre-commit` 自己的判据就是 `git diff --cached -U0 -- 'tests/*' 'src/*'`，照抄它的面。
  - **探针的落点必须在项目的 include 面之内**（#123 retro C5）：本仓 unit 车道按**位置约定**
    收集（`#44`），故**放在 `tests/**/*.spec.ts` 之外（`%TEMP%`、`.scratch/` 等）的探针
    vitest 直接不收集**，读数**恒空** —— 而"读数恒空"**看起来像**"探针没生效"，
    会把人引去查一个不存在的接线问题（#123 实测：两边 `testFilesLine` 都是 `<none>`，
    两次不同落点都如此，第三次落 `tests/__t123_mutation_probe__/` 才有读数）。
    ⇒ 变异探针放 `tests/` 下（唯一前缀 + **跑完即删**），别放仓外。
- **回收要读总账**：跑完扫一眼临时目录（`Get-ChildItem $env:TEMP -Directory -Filter
  'dsh-shell*'`），**本轮那几个档名**不应新增；残留里可能带复制的
  `.credentials.yaml`，看到先解释来源再删。旧档名 `dsh-shellhost-verify-*` 的来源**已解释**：
  那是 pre-`#97` 挂具**失败路径**的泄漏残留（含复制的 `.credentials.yaml`），不由现树任何
  挂具产出（`dsh-shellhost-*` 这一族现役只有 `-real-` / `-tarball-` / `-e2e-` 三处
  `mkdtemp`），本机那 9 个已于 2026-10-17 清掉。
  **过滤器为什么是 `dsh-shell*` 而不是只写一族**：本机有**两个**同源前缀，`dsh-shellhost-*`
  （e2e 挂具）与 `dsh-shell-host-pack-*`（`verify-pack` 的 packdir）——后者**匹配不到**只写
  `dsh-shellhost-*` 的 pattern（`shellhost` 无连字符），于是它长期的残留按本文档的命令扫**恒为 0**，
  `#90` 的泄漏正因此一直没被这条纪律看见（2026-10-17 实测：窄 pattern 命中 1，实际族内 3）。
  一条 pattern 覆盖同源前缀，比每加一族就补一行更不容易再漏。
- **探测自检：0 命中先解释，再采信。** "回读/核对"用的探针本身会**静默**给假阴性，
  值不值得信要看**探测方法**，不是看结论顺不顺眼。四个同族实测形态（2026-10-16 / 2026-10-17）：
  - 原生命令（`gh … --json body` 一类）的输出在 PowerShell 里**按行成数组**，
    `$b.Contains('x')` 判的是"有元素恰等于 x"而非子串 → 四张 issue 正文全部报"不含"，
    换成 `-like '*x*'` 才正确；
  - `Select-String -SimpleMatch` 与 `[regex]::Escape()` 混用会互相抵消（正则被转义成
    字面量）→ 探测关键词**静默 0 命中**，差点误报"文档缺内容"。
  - **大小写**：身份 / 路径 / 哈希类探针用全大写扫，会静默漏掉文件里的另一种写法
    （隐私清理实测：全大写探针 0 命中，而文件里是小写写法）→ 一律 `git grep -i`；
    哈希同理（`git log -S` 区分大小写）。
  - **表格化输出会被重排**：把 `Select-Object Name,LastWriteTime` 这类表格命令与裸字符串
    （`"--- 副本 lib ---"` 这样的头）**混在同一条命令里**时，PowerShell 会在输出末尾**按类型分段**
    重排（实测：三段混排后，表头与表格错位，据此差点判错「副本 `src/` 比 `lib/` 新 ⇒ 构件陈旧」，
    靠哈希对账才纠回）→ 一行一对象（`"$($_.LastWriteTime) $($_.Name)"`）或分开调用。
  判据：**0 命中、全为假这类"整齐"的输出，先给反证（换一种探测方式或人工核一处）再写进证据。**

## 分层：mock 层 vs 真实层

| 层面 | mock 层**能**证明 | mock 层**不能**证明 |
|---|---|---|
| 本仓（harness） | 真实实例启动、真实组合树、真实建会话、真实发出的请求字节、真实工具执行（含真实 PTY 子进程） | — |
| agent 循环 | 真实 `tool_use` → 真实工具执行 → `tool_result` 回灌 | — |
| 供应商侧 | ❌ | 真实端点是否接受（鉴权 / 模型名 / 提示词长度上限 / 字段兼容 / 流式格式差异） |
| 真实模型行为 | ❌ | 模型是否真按预期发起工具调用（注入有效性） |
| 真实工具面 | ❌ | `shell_open` 等**受审批门**工具的审批/沙箱路径（mock 层刻意挑免审批工具，只证"工具面被打通"） |
| 鉴权 | ❌ | mock 层塞的是假 key |

**结论：mock 绿 ≠ 真实调用没问题。**

## 失败归因断言（**最重要的一条**）

允许"环境性失败"存在，但**失败信息绝不能点名本仓新增的行/工具**——
把「环境缺失」与「我的缺陷」机械区分开：

```js
const MY_ROWS = ['pty', 'terminal']            // 本仓新增的 loader 行
const blamed = MY_ROWS.filter(row => message.includes(row))
if (blamed.length === 0) ok('失败只指向 harness 缺失的服务')
else bad('失败归咎于本仓新增行', blamed.join(', '))
```

**为什么必须有**：只写 `package.json` 注册记录而不真安装时，loader 会
`skipping profile bundle: cannot resolve`，但**实例照样起得来、会话照样建得成**——
此时任何"请求里出现 `pty_open`"的断言都会**假绿**（那字符串可能是测试自己塞的）。

### e2e 的安装必须走官方命令

规则与理由（为何 ① 不能省、为何手工 symlink 不算安装）见
[profile-install.md](profile-install.md)。测试里只多两条自有约定：

- **断言"装好了"要看三处**：`dsh.profile.bundles` 含插件名、`dependencies` 有该
  条目、`node_modules/<pkg>/package.json` 存在。只看一条会漏掉"注册了但没装"的
  假绿形态。
- **用共享挂具** `tests/helpers/e2e-install.ts`（三个 e2e 套件共用：安装流程、
  host env 组装、loud-skip 门禁、装箱面），不要在 spec 里各写一套。

### 工具面断言的正确写法

必须断言 **实例真实请求体里的 `tools` 数组**含有本仓工具，
**不能**断言"请求文本里出现过工具名"（后者会把 mock 自己发的 `tool_use` 当成证据）：

```js
const declaredTools = firstBody.tools ?? []
const names = declaredTools.map(t => t.name)
check('实例的 tools 数组含 pty_open', names.includes('pty_open'))
```

- **e2e 用临时 DSH_HOME**（`os.tmpdir` + `--port 0`），不碰常驻实例，也不碰副本的
  profile —— 所以跑测试不需要先同步副本的 profile。

## 写测试时会踩的坑

**领域事实**（RC/alpha 接口差异、typert RPC 参数名三种形态、会话证据只走 RPC、
凭据与路由配对）→ 见 [GLOSSARY.md](../../GLOSSARY.md) 的「#82 RC 锚 vs alpha 的
宿主接口差异」。此处不重复，只记**测试自身**会踩的：

1. **安装必须走官方两步命令**，且**第 ① 步不能省**（否则实例启动毫无输出）。
   见上文「e2e 的安装必须走官方命令」。
2. **实例会另发"会话标题"轻量请求**：抓 agent 主请求要按 `tools.length > 0` 过滤，
   不能取 `captured[0]` —— 取错会把标题请求当第 1 轮（假红）。
3. **kill 实例后必须等子进程退出**（`SIGTERM` → await exit → `SIGKILL` 兜底），
   否则 libuv 断言噪音 + ECONNRESET 污染输出。预期 ECONNRESET 应静音。
   这套「kill 后等退出 + 预算判词（忽略 SIGTERM **和** SIGKILL 也要返回读数，不挂死）」
   **只写一份**：`stopChild()`（`e2e-chain.ts`），三个套件都用它（`#100` 起不要再在 spec 里写一遍）。
4. **`pty_open` 必填 `command`**（在 PTY 上 spawn 的命令）；**`shell_open` 必填 `preset`**
   （launcher preset id）。混淆会得到 `missing required property "command"`
   —— 这是**测试传错参**，不是插件缺陷。
5. **无参 RPC 方法建议自动纠正参数名**（先 `{}` 再 `_request`），别把信封琐事
   变成用例失败。挂具里已实现为 `rpcZeroArg()`（`e2e-chain.ts`）：只把
   `arguments-invalid` 当「形态不对」继续试下一个，其余错误立刻抛。
6. **构建期限制**（tsdown 路径双拼、rolldown 需 Windows node）见
   [#80](https://github.com/ch1bug/dsh-shell-host/issues/80) /
   [#81](https://github.com/ch1bug/dsh-shell-host/issues/81) 与
   [dev-environment.md](../dev-environment.md) §4。
7. **探针 needle 命中的必须是被测系统的输出，回声不算**（`#99`）：拿「轮询 `pty_tail`
   直到 needle 出现」判到达时，**展开值探针**的 needle 要选**只在展开后出现**的形状 ——
   只写裸前缀（如 `PSV-`）会被 `pty_send` 敲进去那行命令的**回声**满足，等于在展开输出
   到达前就判到达（后果与成因见判据本体头注，本文不复述）。这是**选 needle 的纪律**，
   不是「把断言放松」。（与上文「探测自检」是两个面：那条讲**验证手段自身**会静默假阴性，
   本条讲**被测探针**该选什么 needle。）三种正确形状（`#99` 落地时逐条核过）：
   - **展开值正则**：needle 是 `RegExp`，字面命令里同名前缀后面跟的不是数字 —— pwsh 的
     `/PSV-\d+\.\d+/`（字面命令是 `"PSV-$($PSVersionTable.PSVersion.ToString())"`）：
     只有回声时恒不命中；
   - **展开值 + 输出组合**：needle 同时要求**展开后的探针值**与**那条命令自身的输出行** ——
     msys2 的 `/PROBE-UCRT64[\s\S]*\b(MSYS|MINGW|UCRT)/i`（字面命令是
     `echo PROBE-$MSYSTEM && uname -a`：回声里 `$MSYSTEM` 未展开、没有 `PROBE-UCRT64`，
     `uname -a` 的输出行是它的另一半）；
   - **展开值子串**：needle 是只可能由展开产生的裸子串 —— wsl 的 `WSLPROBE-Linux`
     （字面命令里是 `WSLPROBE-$(uname -sr)`）；
   - **命令输出横幅**（严格说不是变量展开，但同属「回声单独满足不了」的类，`#103` 收在同一
     表里）：cmd 的 `ver`，needle 要求 `Microsoft` 前缀（`/Microsoft (?:\[Version|Windows|\[版本)/`），
     回声帧里只有裸命令名 `ver`。
   **例外**：**marker / 往返探针**的 needle 本来**就该**被回声满足 —— coexistence 的四个
   `MARK-*`（`echo MARK-MSYS` 一类）与 ssh 往返的 `SSHOPEN-42` 就是拿「自己敲的字面量」证明
   「没串到别的会话 / 往返通了」，它们断言的是隔离与到达、不是展开值。故本规则**只对展开值
   探针**成立。
   **取证口径**：判据抽成可测纯函数 + 离线**「回声帧 / 展开帧」两输入**断言（真 `pty_send`
   后的分帧到达在集成层是时序相关的，离线层才是确定性形态）；变异口径 = 把 needle 改回裸前缀
   → 离线档**必红**。判据本体与成因**只在** `tests/helpers/probe-needle.ts` 里讲（单一来源），
   离线实例断言见 `tests/probe-needle.spec.ts`，活体用例见 `tests/terminal-machine.spec.ts`。
   **表驱动**（`#103`）：展开值探针的 command + needle **成对**收在该模块的 `EXPANDED_PROBES`
   表里（一条 `ExpandedProbe` 记录 = command + needle + 回声可满足形态 + 展开帧样本），machine
   用例只引用常量；**新增一条展开值探针 = 表里加一行**，离线档自动对它断言「回声帧不命中
   （且命中它的回声可满足形态）+ 展开帧命中 + 行尾 LF/CRLF 都不影响命中」，不用改用例。
   marker / 往返探针不进表。

### 真实层的断言取舍（领域事实见 GLOSSARY）

三条**静默失败**形态决定了真实层怎么写断言 —— 事实与成因见
[GLOSSARY.md](../../GLOSSARY.md)「#82 RC 锚 vs alpha 的宿主接口差异」：

1. **凭据与路由配错** → 实例不报错（`turn/end` 正常、stderr 空、`usage=0`）。
   故断言两条：`usage > 0`，且 **`assistant/attempt` 无 failure**；账号路线额外断言
   选中的 provider 是 `deepseek-account`（非 `deepseek-official`）。
2. **模型路由必须先选再发**（`create` → `modelCatalog` → `selectModel` → `prompt`）。
   乱序的形态是 turn 不起 —— 且**没有错误可断言**，只能靠超时暴露。
3. **证据只走 RPC，不读会话文件**，且别拿 `llmMs`/`toolMs` 当完成判据
   （本宿主上可能为 0 而 turn 已完成）。计费看 `tokenUsage`，执行看 `tool/result`。
