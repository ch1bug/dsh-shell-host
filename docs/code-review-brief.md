# 复核 brief（`/code-review` 专用）

**谁读**：审阅阶段（`/code-review` 的两个轴 subagent）。**实现阶段不必读** ——
实现 agent 的上下文压力最大，标准不该压给它；审阅 agent 拿到 diff、没有探索成本，
由它承担标准。

**入口**：`/code-review` 技能（`.claude/skills/code-review/SKILL.md`）；本文只定
**本仓怎么组装那两份 brief**。

## 1. 定固定点

- 默认固定点 = **`HEAD`**（起手快照）。
- **工作还没提交：先 `git add -A`，再用 `git diff --staged`** —— 否则**新增文件不出现**
  在 diff 里。这不是理论风险：本仓 `docs/dev-environment.md`、`tests/helpers/e2e-install.ts`
  这类新文件一旦漏掉，就等于**审了个残缺面**（本会话实测踩过）。
  - 若只想审未暂存的部分，用 `git diff --staged --stat` 先确认**新增文件在列**。
- 已提交：`git diff <固定点>...HEAD`（三点，对 merge-base）。
- 先验固定点可解析、diff 非空，**再**派 subagent —— 坏 ref 要在这一层炸，
  不要炸在两个 subagent 里。
- ⚠️ **派发前重核索引与磁盘一致，并在 brief 里写明"当前是哪种固定点形态"**
  （批 D 聚合 A3；`#129` C1 + C9，两票各踩一次）：
  - **C1（`#129` 实测）**：`git add` **之后又编辑**了文件 ⇒ `git status --short` 变 **`MM`**
    （索引与磁盘分叉）⇒ 复核者按 §1 拿到的是**过期快照**。两轴**各自独立**报出同一条"头注行号过时"，
    真因不是头注写错，而是**它们审的那份不是当时的那份**。
    ⇒ 派发前**重新 `git add`** 并确认第一列**无分叉**（`M ` 可以，`MM` / ` M` 不行）。
  - **C9（`#129` 实测）**：票**已经提交**了，而 brief 仍写"固定点在索引、用 `--staged`"
    ⇒ brief 随会话推进**悄悄过期**。该轴按 `RECOVERY DISCIPLINE` **没乱改**、
    报告漂移并改用 `<ref>...HEAD` —— 处置正确，但**本可以不给它出这道题**。
    ⇒ brief 里必须写明**当前处于哪种形态**，并给一条复核者能**自验**的命令
    （`git status -sb` + `git diff --staged --stat`）。
  - **正例（`#126`）**：派发前重核 `git status --short` = `M `（无分叉），
    且**对已提交的 commit 派发**（而非索引）⇒ 该陷阱**未复发**。
- **票内顺序写死为** `改 → 单档 → 两轴 → 按发现改 → 全量 → 提交 → 车道`（批 E 聚合 E1，计次 ×2）：
  `#103` 先跑全量、后派两轴 ⇒ 意见一改那轮全量就作废（Standards 轴当场报成硬违规）；
  `#100` 变异**复原**后只复跑了被变异的那一档 ⇒ tarball / 真实层的绿早于挂具最后一次写盘，
  两轴各报一次「交付态缺读数」。⇒ 全量必须落在**两轴之后、最终树之上**；它的验收面是
  [agents/TESTING.md](agents/TESTING.md) 的「验收口径的套件必须在最后一次写入之后起跑」。

## 2. 定 spec 源

1. 提交信息里的票号 → `gh issue view <NN> --repo ch1bug/dsh-shell-host`；
2. 票上若有 **agent brief 评论**（`## Agent Brief` / `> *This was generated by AI during triage.*`），
   它是**权威契约**，优先于原始正文与讨论 —— 两者冲突时以 brief 为准；
3. 都没有 → 问 human 要 spec；仍无则 Spec 轴**跳过并明说"无 spec"**，不要猜 AC。

## 3. standards 源（本仓）

- [AGENTS.md](../AGENTS.md)（导航 + 沟通语言 + Build & verify）
- [GLOSSARY.md](../GLOSSARY.md)（已验证的上游事实 + grill 决策 D1–D13）
- [adr/](adr/) —— 尤其 **ADR-0012**（只挂自有 id 行、不接管上游行）、
  **ADR-0013**（tools-only，执行器 world 已移除）、**ADR-0014**（无 CI 的边界：本地守卫可、CI 服务不可）
- [agents/TESTING.md](agents/TESTING.md)（分层 / 证据纪律 / loud skip / 失败归因 / e2e 安装规则）
- [dev-environment.md](dev-environment.md)（隔离契约、宿主锚点、构建坑）
- [README.md](../README.md)（验证段）

**邻近文件的既有风格**：`src/` 用双引号 + 分号（TypeScript，`verbatimModuleSyntax` 下
`import type` 显式）；`tests/*.spec.ts` 用 vitest、按位置收集；文档以中文为主
（AGENTS.md 顶部即有"与人沟通一律用中文"）。

- **决策状态类事实**（判断项转硬）：状态 / 证据文件里，**未拍的决策不得写成「已拍」** ——
  用 `待拍` 与 `已拍（<日期>）` 两种标记，reviewer 逐条核。这是"引用类事实"的**姊妹类**：
  本仓实测踩过 —— 把「human 已拍：立票」写进 `.scratch/batch-state.md`（当时还没拍），靠自查才发现。

**形状移植要重核参数**（判断项，给 Standards 轴）：diff 里凡从**姊妹档复制**来的挂具 /
环表 / 报告形状，逐参数核它在本档的诊断面（截断长度、预算、超时）与头注承诺 —— 照抄会
把上一档的取舍一起搬来。样例见 §7。

- **公共化（把重复块提成共享挂具）要重核"哪一档的假设被带走"**（批 E 聚合 E2，`#100` 实测）：
  上一条管**复制方向**（从姊妹档抄形状），这条管**反方向**（把 A 档已有实现提成共享挂具给 B 档用）。
  A 里**硬编码的假设**会静默变成 B 的**行为变更** —— `#100` 实测：`startInstance()` 的就绪判据
  原本只服务 mock 两档（`127.0.0.1` + 必带一次性 token），真实层改用同一挂具后，它原来那套
  `/dsh web: (http:\/\/\S+)/`（任意 host、无 token 也接受）被换掉：宿主就绪行形态一变，红的是
  **120s 超时**而不是原有诊断，且回环地址被钉进真机档。
  **落法**：提共享前逐参数对照 B 档旧实现，差异要么留成**参数**，要么在落地文档**显式声明为
  行为变更**；"两档从此共用一份" ≠ "两档行为不变"。

本仓**没有** `CODING_STANDARDS.md`、**没有 lint**：判断类标准散在上面这些文件里。
优先级固定为 **文档化标准（可判硬）> Fowler smell 基线（永远是判断项）**；
工具已强制的（typecheck）跳过。

- **改上界 / 下界证明时要重核"同一用例的累积判据"**（批 D 聚合 A11，`#129` C8）：
  §3 那条"形状移植要重核参数"的**近亲**。把某个等待从"固定 sleep"改成 `waitUntil`（上界证明）时，
  会**顺带改掉**同一用例里由多行 `stillHeldFor` 累积出来的**下界**
  （`#129` 实测：旧三行把下界推到 **t=145ms**，末行换掉后只剩 **65ms**）。
  **下界与上界是两个方向的判据**，改一个必须**重新声明另一个**：
  在落地文档 / 注释里明确写出**新下界是多少、由哪几行守**。
  （该变化常常是**对的** —— `#129` 旧 80ms 预算对实测 max97ms 只剩 3ms，
  那种"随时会被打红的下界"本身就是**坏的下界**；但**对的变化也必须显式声明**，否则复核者会当成缺陷。）
- **允许复核者自造"对照实现"，但它的结论必须由一手源仲裁**（批 D 聚合 A2；`#129` C2 + `#126` D8，计次 2）：
  复核者（或你自己）另写一份解析器 / 复刻实现来对拍时，拿到的读数**只能和那份实现一样可信**。
  - **实测（`#126`）**：Spec 轴用**自己的"严格版"**实现当规格，报"实现错" ——
    而它的"严格版"**漏了规格的一条**（闭栏缩进上限），还引了一个**不相干**的规格例作依据。
    我按 `commonmark-spec` 一手原文裁定**质疑不成立**、实现正确。
  - **落法**：凡"我另写了一份 X 来对拍"产生的结论，**必须同时引一手规格原文
    （或规格自带的 conformance 例）作仲裁**，不得把复刻实现当基准。
    与 `agents/TESTING.md` 的「探测自检：0 命中先解释，再采信」**同族不同层** ——
    那条管**探针**，这条管**对照物**。

## 4. smell 基线

从 `code-review` 技能正文取（Fowler *Refactoring* ch.3 的 12 条），**整段粘进 subagent
prompt** —— subagent 没有你的上下文（不会自带基线）。**别复述成一句话摘要**，摘要会让基线失效。

## 5. 两轴 brief 模板

两个 subagent **同时**发（一条消息两个调用），各给"diff 命令 + 提交列表 + 该轴材料 + 它的 brief"：

- **Standards 轴**：diff 命令 + 第 3 节清单 + 粘好的 smell 基线 + **本仓的证据文字面**
  （`git log -1 --format=%B` 的提交信息与该票落地文档 `.scratch/<票>-landing.md` —— 本仓要求的
  证据三要素「命令 + 退出码 + 证据路径」只在这两处出现，diff 里看不到）+ 要求
  "逐文件/逐 hunk 报：违反哪条**文档化标准**（指名文件 + 规则）；命中哪条 smell（引用 hunk）；
  **核证据文字面里的事实**（引用类事实逐条核到源；决策状态类事实：未拍的不得写成「已拍」，见第 3 节）；
  区分**硬违规**与**判断项**；工具已强制的跳过；<400 词"。
  - ⚠️ **派发时「证据文字面」尚不存在**（本仓流程是 先两轴 → 后全量 → 再提交 → 最后落地文档；
    `#144` 实测）：就在 brief 里列**两份清单** —— 「已产生」与「**未产生**」，并写明各自为什么还没产生。
    别让复核者把「尚不存在」判成缺项（`#144` 的写法可作样板）。
- **Spec 轴**：diff 命令 + spec 原文（或 agent brief）+ 要求
  "(a) 缺失或只实现了一半的需求；(b) 票面没要求的行为（scope creep）；(c) 看似实现实则错的地方；
  每条引用 spec 原文；<400 词"。

## 6. 出报告

两轴**分开**呈现（`## Standards` / `## Spec`），**不合并、不重排、不跨轴选一个最优** ——
两轴故意隔离：合标准的可能实现错了，实现对的可能坏了约定，合并正好让一轴掩盖另一轴。

## 7. 本仓已修过的复核发现（回归样例）

- **新增文件漏进 diff**（固定点写法的坑，见 §1）
- **文档与既有文件冲突**：AGENTS.md 与 `TESTING.md`/`dev-environment.md` 复述同一条规则
  （应"单一来源 + 指针"，本会话清过两处）
- **陈旧事实**：`GLOSSARY.md` 里 `dsh-tools` 版本号未随 #82 的 RC 锚更新
- **e2e 安装绕开官方命令**：用"手写注册记录 + 手工 symlink"代替 `dsh plugin add`
  （违反 `profile-install.md`，且把违规做法固化进测试）
- **过时命令**：README 的 Build & verify 还写 `pnpm ...`（#79 起已改 `node --run`）
- **同一 diff 内引用的事实自相矛盾**：`#83` 的文件头写 `8094b0d`、用例注释仍写 `629398c`
  ——**两个轴都没抓到**，靠自查才发现。引用类事实（提交哈希、路径、版本号、命令）在多处出现时
  **逐一比对**，并核到源（`git log -S <符号>` / `git log --oneline -1 <hash>`）；存在但写错的
  引用，机械检查抓不到，只能靠这一条。
- **before/after 对比里的「改前」描述也是引用类事实**（批 E 聚合 E5，`#100` 实测）：写"某档此前
  只共用 X"这类**改前状态**时照抄旧句，而 HEAD 实际是"X 与 Y"（`import { MY_ROWS, stopChild }`）
  —— Standards 轴判引用类事实错。落法：动笔前 `git show HEAD:<file>` 或 `git grep` 核到源，
  别照抄旧句；这条是"引用类事实"的第三类（前两类：路径/哈希/版本号/命令、别的文件的行为）。
- **照搬姊妹档的形状，把它的取舍也搬来了**（`#97`）：环表挂具从装箱档复制时，`oneLine(error,
  max = 300)` 的截断把真实层唯一的诊断尾巴（stats / events / stderr）吃掉；头注「每环恰一行」
  也强于实现（环外异常那一条），连「环不互喂状态」都是抄来的事实错误。两轴都报了同一处。
- **注释里的引用类事实也是引用**（批 G 聚合 G16；`#146` 实测，两条硬违规都来自注释）：注释里凡点名
  「某文件 / 某票 / 某测试用了 X」，都要当场 `git grep` / `gh issue view` 一次 —— 「顺手一写、没 grep」
  的注释被 Standards 轴判硬违规两次：「README / tests cite this constant」（实际只有本文件用）、
  「`#144`/`#149` precedent」（`#144` 当时**还没有**落地物）。

## 8. 没有 review 轴的提交（retro / chore 落地）

两个轴只在 `/code-review` 里跑；retro 落地、纯 chore 这类提交**没有**这两道闸，而同类错误照样会从
那条路进来：同一天两次落地里，同一类假事实出现**两次** —— 一次是注释误称「两个 mock 档的 boot 环同序」
（实为反序；`591b666`，Standards 轴抓到），一次是注释误称「本仓树的 `lib/` 只被
`tests/built-artifact.spec.ts` 读」（`scripts/verify-pack.mjs` 也读它；`3023fc0` 这次 chore 里
**没有轴**，自查才发现）。

落地者因此按 §1 的固定点写法过 diff 时（`git add -A` + `git diff --staged`），把 §7 那两条**自己**核一遍：
**引用类事实**（提交哈希、路径、版本号、命令、别的文件的行为）逐条 grep 到源，**照搬来的形状**逐参数
核它在本文档的诊断面。这两条不需要第二个人，只需要真的去查一次。
