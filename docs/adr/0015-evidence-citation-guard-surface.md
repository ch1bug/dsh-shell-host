# ADR-0015: 证据引用守卫读 `.scratch/` —— 本机有牙，推送树上响亮跳过

- Status: Accepted
- Date: 2026-10-19
- Deciders: human（2026-10-19 grill `#132`，六问逐条拍板：Q1=D / Q2=A / Q3=D / Q4=B / Q5=A / Q6=A）
- Context: `#130` 关闭时把「机械化守卫」那半留给 `#132`，并给了字面判据；
  而该判据的产物面（落地文档）全在 `.scratch/`（`.gitignore:4`），**不在 vitest 收集面** ——
  「守卫扫哪一面」必须先拍，且这个答案**约束**同族的 `#127` / `#128`
- Related: ADR-0014（本地守卫允许、CI 服务不允许）、`#78`（引用腐烂检查本体）、
  `#112` AC5（同族守卫别各写一套）、`#127` / `#128`（见 Consequences）

## Context

`#130` 给的口径是：扫落地文档 / 证据表格里的每个「证据路径」格子 → 打开该文件 →
若文档同时声称了某个退出码（`exit=0` / `EXIT=0` / `FROZEN_EXIT=0` 这一类），
则该文件内容须**包含**该退出码字面（或该声称须显式标注「未落盘 / 读数为 stdout」）。
它只关掉 `#130` 表里**第 1 次**那一类（结论为真、证据为假），纯本地、不违 ADR-0014。

难点是**产物面**：这种「路径 + 退出码声称」的配对**只出现在 `.scratch/<NN>-landing.md`**，
而该目录 gitignore、无 git 历史。票面给了三选一：(a) 扫已提交文档、(b) 落地文档升格进仓、
(c) 只保留纪律。grill 实测后另有第四条：(d) 守卫把 `.scratch/` 当**数据源**读。

四条路的读数（一手日志 `.scratch/t132-final-readings.log`，`exit=0`；`.scratch/` 已
gitignore，该日志是本机上下文、不进仓，故数字**原样**抄在这里）：

- **(a) 已提交文档面没有牙**：全部已提交文档里 `.scratch/` 的**具体**引用 33 条
  （24 条现在还在盘上、9 条不在；其中 3 条是正则把 `{A,B}` / `<批>` 模板截断所致），
  而**同行带 `exit=` 声称的 0 条** ⇒ 照 `#130` 口径立起来**恒绿**。
  更本质：被引证据全是 gitignore 的，干净 clone 上一条都不存在 ⇒ 判据无法兑现。
- **(b) 升格进仓撞隐私门**：只搬「引用方」（落地文档）时，被引的 `.log` 仍不进仓，干净 clone
  上照样开不开；连日志一起搬则 `privacy-scan` 的 `scanText` 命中 **283/462** 份 `.log`
  （落地文档本身只 1/10）—— 本仓是 PUBLIC 仓（`AGENTS.md`），这条路基本封死。
- **(c) 只保留纪律**：零成本，但 `#130` 第 1 次那类仍无闸。
- **(d) 读 `.scratch/`**：不搬任何东西、不改「临时产物放 `.scratch/`」的既有约定、零隐私代价；
  牙齿落在**写落地文档的那台机器**上（正是出事的地方）。代价：推送后的树上不可复跑。

## Decision

**1. 数据源 = `.scratch/`（票面之外的第四条，2026-10-19 拍 Q1=D）。**
守卫是新 spec `tests/evidence-citations.spec.ts`，以 `.scratch/` 为**数据源**读取
（不把任何产物搬进仓、不改 `.gitignore`）。目录或其下文件缺席时**响亮跳过**
（`!! SKIP (loud)`，照 ADR-0014 与套件的 loud-skip 惯例）——绝不静默当绿。
推论：本守卫在**干净 clone / msys 部署副本 / pre-push 车道**里恒为 loud skip，
汇总里表现为 `PASS*`；这是**有意的**，不要把它当"已验证"。

**2. 判定面 = 只判「矛盾」与「不存在」（Q2=A）。** 逐条：
- 被引证据文件**不存在** ⇒ 红。
- 文件里**有**退出码读数且与声称值**相反** ⇒ 红。
- 文件里**没有**任何退出码读数（例如 privacy 扫描日志、`.mjs` 驱动脚本）⇒
  **响亮声明不判**（`!! SKIP (loud)`）——「不含」不等于「相反」，这是 `#130`
  字面判据的**假红源**：今日面内 19/50 个判定位落在这一类。
- **修正 `#130` 字面口径**：本仓约定是 stdout 落 `.log`、退出码落**同名 `.exit` 边车**
  （实测 `.log` 462 / `.exit` 57，57 条边车**全部**有同名 `.log`）。故「文件须包含声称值」
  这条字面要求在今日落地文档上会红 3 条**正当**引用 ⇒ 判据改为上面的「矛盾才红」。

**3. 多声称行出判定面（Q3=D）。** 一行里出现 ≥2 个**不同**退出码声称时，该行整行
不判、只留响亮声明；判据只判「单声称行」。今日面内这类行 3 条（`113-landing.md` 1 条
+ `batch-state.md` 2 条）。理由：为 1/50 的面造「就近配对」解析，误配对的代价是**假红**，
而那正是第 2 条要躲的东西。

**4. 扫描面 = 有证据行义务的三类（Q4=B）。** `AGENTS.md` 只对三类文件明文要求证据三件套：
`.scratch/<NN>-landing.md`（落地文档）、`.scratch/batch-state.md`（批次进度行）、
`.scratch/retro/*.md`（retro 候选）—— 共 26 档。今日面内：**115 声称行 / 50 个判定位
（31 含 / 19 无 exit 信息 / 0 红）**。
**不纳入**：归档（`batch-archive-*`）、交接文档、issue 回读、探针笔记（共 76+27 档）。
理由有两条：它们没有证据行义务；且归档沿用本仓「红 → 绿」取证文体（同一行既写
`typecheck exit 0` 又引红运行的 `.log`），今日实测 `batch-archive-118-117-92-95-91.md:40`
就是**唯一**会假红的那条。

**5. 声称文法（本会话自定的实现细节，由 implement 用合成用例锁住）。**
`[A-Za-z_]*EXIT` 形态、大小写不敏感、允许 `=` / `:` / 空格分隔（`exit 0` 也算）。
依据：严格只认大写 `EXIT=` 时面内只剩 10 个判定位（landing 6 + retro 4），牙太弱；
放宽后 50 个、且 0 红。
⚠️ **边车接入**留给 implement 实测：被引文件是 `.log` 且存在同名 `.exit` 时，边车一并
当载体，不要只读 `.log` —— 但**接入后必须实测面内是否仍 0 红**并把读数落档（本文的数字
是**未接边车**的口径）。

**6. 次-2（状态 / 断言类声称）只补纪律，不机械化（Q5=A）。**
`docs/agents/TESTING.md`「证据纪律」补一条：凡是「已推送 / 已关闭 / 已在 list 里 / 已同步」
这类**当刻状态**声称，写之前先跑那条能证伪它的命令（`git log origin/main..HEAD`、
`git status -sb`、`gh issue view <n> --json state`），读数写进证据行。
不机械化的依据：仓内 26 档文档里这类字样 53 处，**绝大多数是历史叙述**（不是当刻断言）
⇒ 守卫会大面积假红；而可机械化的子集只有 git 真值（`gh` 要联网，ADR-0014 明禁），
它一 push 就过期 ⇒ 那是**新判据、新票**，不在本票顺手做。

## Consequences

- **正面**：守卫第一次真正有牙（`#130` 第 1 次那类「结论为真、证据为假」有了本地闸），
  且代价是零搬动、零隐私风险、零约定变更；判定面与 `AGENTS.md` 的**义务面**对齐
  （26 档全都是被明文要求带证据三件套的文件）。
- **代价（显式）**：守卫只在「有 `.scratch/` 的那棵树」上有牙齿。干净 clone、msys 部署副本、
  pre-push 车道上它恒 `!! SKIP (loud)` ⇒ 汇总里是 `PASS*`，**绿不等于验过**。
  这是有意的取舍：另一条路（升格进仓）要付 283/462 的隐私代价，第三条路（只扫已提交文档）
  是恒绿的空闸。
- **覆盖面诚实声明**：全 `.scratch` 里有 **218 行**声称带退出码但**没有任何具体证据路径**
  （行内读数形态）。它们结构上进不了本判据的面 —— 本守卫覆盖的是「有载体可打开」的那一半。
  要给那一半上闸，得另立判据（例如要求「行内读数必须配 `.exit` 边车」），不属本 ADR。
- **对 `#127`（`[History: …]` 豁免粒度）的约束**：
  - 新守卫必须**复用 `blocksOf`**（`#112` AC5 同族守卫别各写一套）⇒ 它**自动继承整行豁免**：
    落地文档里带 `[History: …]` 的行整行出证据判定面。
  - ⇒ `#127` 的三种方向都会**改变本守卫的判定面**（豁免变窄 ⇒ 更多行进面）。
    **`#127` 的验收面必须把 `tests/evidence-citations.spec.ts` 纳入并逐条过一遍**，
    否则改窄之后本守卫的行为变化无人验。
  - ⇒ 新守卫**不得新造第二套豁免词汇**（`[Quoted:]` / `[引述:]` 之类）。「引述失败」
    （例如 `113-landing.md` 里那句「把 X 引作 exit 0 而它其实是 1」）若要免判，只能复用
    既有 `[History: …]` —— 而**那要先由 `#127` 拍粒度**，因为整行豁免会把同一行的判据
    说明一起移出扫描面（`#93` / `#94` 已两次实证）。
- **对 `#128`（`~/…` 活体判定基准）的约束**：
  - 本守卫解析的是 `.scratch/` 内的相对路径，**不涉及 `~`**，也**不得**引入第三套路径
    展开基准（现役两套：`os.homedir()` / msys home，均不适用于本守卫）。
  - 若 `#128` 选「运行期探测 msys home」，**不要**把这个基准塞进通用的路径解析层：
    本守卫的基准是 `.scratch/`（相对仓库根），与家目录无关；否则同一条 `~/<name>` 会在不同
    守卫里落点不同。
  - 反向：本守卫若日后要判 `.scratch` 文档里引用的 `~/…` 证据（今日 0 条），
    必须复用 `#128` 定下的基准，不得自造第三套。
- **待办（下一票，`implement`）**：`tests/evidence-citations.spec.ts`（数据源 `.scratch/`、
  判据按 Decision 2/3/4/5、复用 `blocksOf`）+ `docs/agents/TESTING.md` 的次-2 纪律一句。
  本 ADR 只记决定，不含实现。

## 修订（2026-10-19，`#127` 拍板后）

`#127` 的 grill 同日拍板：豁免粒度改为**括号内点名制** —— `[History: …]` 括号里被反引号
包住的 token 才出判定面，作用域 = **同块**（`.md` 同行 / `.ts` 同注释块），且豁免是
「把命中的 token 从块内移除」而**不是**「整块丢弃」。真树读数（`#127` grill 实测）：
维持整行/整块（C）0 红、标记之后那段（A）3 红、括号内点名（B）4 红 —— 而 A 红得少是因为
它把 checker 头注 33 行之后的 50+ 行判据说明一并移出了扫描面。

⇒ 上文「对 `#127` 的约束」里**「新守卫自动继承整行豁免」这句已被本次拍板覆盖**：
新守卫继承的是**点名 token 出判定面**（头注与合成用例在 `implement` 时写入
`tests/doc-references.spec.ts`）。其余三条约束不变：

1. `#127` 的验收面**必须**把 `tests/evidence-citations.spec.ts` 纳入并逐条过一遍；
2. 新守卫**不得**新造第二套豁免词汇 —— 「引述失败」只能复用 `[History: …]` 并在括号里
   点名被引路径；
3. 粒度变更同时**取消了行级围栏豁免**（旧口径下带标记的行免受 `#126` 的围栏配对判定；
   新口径下点名 token 不移除整行）。实测今天无依赖；若要恢复该豁免，属新机制、新票。

## 修订（2026-10-19，`#128` 拍板后）

`#128` 的 grill 同日拍板：`~` 的活体基准 = **msys home**（`detectMsysRoot()` + 运行期用户名
推导，推导不出 ⇒ 响亮跳过；**不硬编码用户名**）；扫描面**含 `docs/adr/`**（与同族判据 5 同面）。
实测读数：52 条命中、去重 16 个 token —— 按 `os.homedir()` 判 43 条缺失、按 msys home 判 6 条、
"任一存在" 4 条；两套所指的分账说明同仓文档里 `~` 曾有两个所指，故取单一基准 + 写法归一
（Windows home 一律 `%USERPROFILE%`、DSH 家目录写 `$DSH_HOME`、占位写 `~/<name>`）。

⇒ 上文「对 `#128` 的约束」三条**原样成立**且已被这次拍板落实（本守卫基准 = `.scratch/`，
与家目录无关；`~` 的基准只活在 `tildeRefsIn` 一族里，不进通用解析层）。
